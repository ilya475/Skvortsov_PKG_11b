# Лабораторная работа № 4 — «Базовые растровые алгоритмы»

**Автор:** Скворцов Илья · БГУ · 2026

Исходный код и исследовательский отчёт собраны по требованиям «Лабораторной работы 4»; реализованы четыре обязательных метода и расширенные задания для группы 10А. Это самостоятельное статическое веб-приложение. Для учебной демонстрации не требуется интернет-подключение, npm-зависимости или серверный API (кроме локального HTTP-сервера при запуске на своём компьютере).

## Запуск приложения

**Windows / Linux / macOS (достаточно Python 3):**

1. Распаковать архив в отдельную папку.
2. Открыть терминал **в папке с `index.html`**.
3. Выполнить `python -m http.server 8000` (на некоторых Windows — `py -m http.server 8000`).
4. Открыть в Chrome, Edge или Firefox `http://localhost:8000/`.

Нельзя просто открывать `index.html` через `file://`: браузер может запретить загрузку JS-модулей и Web Worker. Встроенный `python -m http.server` устраняет эту проблему. Если порт 8000 занят, можно использовать порт 8080 в обеих командах.

## Возможности

- **Четыре обязательных алгоритма:** пошаговая растеризация отрезка, ЦДА (DDA), обобщённый алгоритм Брезенхема для 8 октантов, Брезенхем для окружности с восьмикратной симметрией.
- **Дополнительные алгоритмы:** сглаженная линия Ву с физически вычисляемой долей яркости соседних пикселей; целочисленная растеризация конических сечений по конечным разностям Питвея (поворачиваемый эллипс и параболическая дуга через контрольную точку).
- **Дискретная математическая сетка:** 43 × 43 ячейки, оси OX/OY, метки координат, увеличение ячеек 8–25 px. Целая пара `(x,y)` соответствует центру клетки; индекс массива `[x+Oₓ, Oᵧ−y]`. Положительное направление Y вверх.
- **Пошаговое исполнение:** кнопки вперёд/назад, анимация, таблица до 12 первых шагов, параметр ошибки Брезенхема или доли яркости α Ву. Кнопка восьми октантов последовательно подставляет контрольные отрезки.
- **Независимость вычислений от отображения:** алгоритмы ничего не рисуют; только вызывают `target.setPixel(x, y, intensity)` и записывают флаг/яркость в `VirtualGrid`. `GridPainter` отдельно рисует увеличенные квадраты, оси и подписи по итоговому массиву. Canvas lineTo, arc, ellipse и stroke для построения геометрии не применяются.
- **Бенчмарк без времени UI:** Web Worker создаёт 100 000 отрезков, равномерно распределённых по 8 октантам, и 50 000 окружностей разных радиусов. Замер производительности — `performance.now()` только вокруг обработки матрицы; таблица и 3 графика строятся после измерений. Доступен экспорт CSV. У всех опытов фиксированный seed генератора случайных чисел.

## Автоматические тесты и новый прогон

Для локальной проверки нужен **Node.js >= 18**. Сторонние библиотеки не требуются:

```sh
npm test
npm run test:extended
npm run benchmark
```

Последняя команда запускает новый стресс-тест и показывает результаты в терминале; время на вашем компьютере закономерно может отличаться от времени в отчёте. **В отчёте приведены данные ранее выполненного и сохранённого реального прогона, а не значения, заданные константами.**

## Публикация для сдачи (обязательно по методичке)

1. В личном аккаунте GitHub создать **публичный** репозиторий, например `raster-lab4`.
2. Загрузить в корень репозитория содержимое этой папки, в том числе `index.html` и `src/`. **Не загружайте ZIP как единственный файл:** разместите распакованные файлы.
3. В репозитории: `Settings → Pages → Build and deployment → Deploy from a branch → main → /(root) → Save`.
4. Когда появится публичная страница, проверить загрузку алгоритмов и Web Worker, скопировать действующий адрес вида `https://<username>.github.io/<repo>/`.
5. Внести **реальный адрес** в раздел 15 отчёта Word перед сдачей и проверить, что ссылка доступна без авторизации.

Приложение подготовлено для GitHub Pages (нет абсолютных путей и серверной части), но сам сайт не опубликован автоматически: для этого нужен аккаунт владельца и реальное действие публикации. Не указывайте в отчёте несуществующий URL.

## Важные замечания

- Бенчмарк сравнивает *эту конкретную реализацию* на *одном устройстве*: оценки времени и ускорения не являются универсальными физическими постоянными.
- Поворот эллипса задаётся углом, из которого **один раз** вычисляются два целочисленных диаметра; последующее ядро инкрементальной коники не вызывает тригонометрические функции. При некоторых крайне вырожденных комбинациях параметров построение сообщает о невозможности полного обхода вместо молчаливого зависания.
- Парсер команд принимает целые числа; построение в видимой области может обрезаться по границе 43×43 ячеек. Растр виртуальный, координаты за пределами матрицы безопасно игнорируются.
