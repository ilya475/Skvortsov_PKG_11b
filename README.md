# Лабораторная работа №3 — цифровая обработка изображений

**Выполнил:** Скворцов Илья, **группа 11**. 2026 год.

Это **упрощённая версия** предыдущего проекта: функциональность приведена к набору методов, представленному в присланном примере `lab3`. Веб-приложение работает полностью в браузере на HTML/CSS/JavaScript и пригодно для **GitHub Pages** без сборки и установки зависимостей.

> Важно: в методических указаниях вариант определяется **номером в списке**, а не номером группы. Этот набор из шести методов соответствует варианту **11 из предоставленного примера**. Номер студента по списку группы в исходных данных не указан.

## Что есть в приложении

1. **Линейное контрастирование** по выбранным процентилям (например, 2–98 %).
2. **Локальная бинаризация по среднему** в заданном нечётном окне.
3. **Локальный метод Ниблэка** `T = μ + kσ`.
4. **Адаптивный метод Сауволы** `T = μ(1+k(σ/R−1))`.
5. **Автоматический глобальный метод Оцу** с максимизацией межклассовой дисперсии.
6. **CLAHE**, локальное выравнивание гистограмм с ограничением контраста.

Также реализованы: восемь тестовых PNG, загрузка собственного изображения (или перетаскивание), настройка параметров, выбор Clamp/Reflect, исходный и обработанный кадры, две сравнимые гистограммы, скачивание PNG, числовые характеристики, тестовый протокол и кнопка автопроверки.

В дополнениях к методичке требуется ручной доступ к памяти: реализовано через `Uint8ClampedArray`, `Float64Array` и циклы. Для локальной статистики используются **две интегральные таблицы SAT**. Обработка идёт в **Web Worker**; большие кадры можно делить на 1, 2 или 4 потока. Готовых фильтров Canvas/OpenCV нет. **Результат всегда в оттенках серого**; исходное цветное изображение не изменяется.

## Загрузка на GitHub Pages

1. Распакуйте ZIP.
2. Создайте публичный репозиторий на GitHub и загрузите **содержимое архива в корень**. Файл `index.html` должен оказаться в корневой папке выбранного репозитория.
3. В репозитории откройте **Settings → Pages** и выберите **Deploy from a branch → main → /(root)**, затем Save.
4. Сайт появится по адресу `https://<логин>.github.io/<репозиторий>/` (публикация может занять некоторое время).
5. Веб-отчёт доступен через ссылку **«Открыть отчёт»**, PDF — через ссылку **«PDF»** внизу страницы.

Локально веб-страницу запускают через любой статический HTTP-сервер, например из корня проекта:

```bash
python -m http.server 8000
```

Затем открыть `http://localhost:8000/`. Если открыть `index.html` двойным кликом через `file://`, загрузка ES-модулей и Workers может быть заблокирована браузером.

## Как провести демонстрацию

1. Выберите **«Малоконтрастная сцена»**. Примените «Линейное контрастирование», затем CLAHE. Обратите внимание на два разных изменения гистограммы и интервала P5–P95.
2. Выберите **«Документ с неоднородным освещением»**. Сравните Оцу, локальное среднее, Ниблэк и Сауволу (окно 31×31, k=0,20, R=128). В отчёте эти результаты сверены с эталонной маской по Precision, Recall, F1.
3. У Сауволы измените k с 0,20 до 0,34; обратите внимание, как исчезают некоторые тонкие штрихи текста.
4. Выберите **«Проверка границ»** и сравните Reflect/Clamp для Ниблэка при окне 31×31. В отчёте сравнение показывает 397 отличающихся пикселей.
5. Выберите **«Большое изображение»** и «Локальный порог — среднее» (31×31); обработайте с 1, затем с 4 Workers. Скорость зависит от компьютера. Результат должен совпадать.
6. Разверните «Тестовая база и экспериментальный протокол» и «Проверка алгоритмов»; выполните проверки.

## Тестирование и воспроизводимость

Для модульных тестов нужен Node.js 20+, но **для веб-приложения Node.js не нужен**:

```bash
npm test
```

**Результат на контрольном запуске: 31/31 тестов.** Проверяются математика Оцу, SAT, Reflect/Clamp, совпадение с прямым расчётом локальных окон, эквивалентность полос и другое. Браузерная проверка также подтвердила нулевое число отличий RGBA-байтов при 1 и 4 Workers на кадре 1680×1050.

Для полного пересчёта изображений и отчёта (это нужно **только для разработки**) можно использовать Python 3 с Pillow, NumPy, Matplotlib, Mistune, BeautifulSoup4 и WeasyPrint, а также Node.js:

```bash
python tools/rebuild_experiments.py
python tools/browser_qa.py
python tools/build_report.py
```

`browser_qa.py` использует тестовый встраиваемый запуск исходных JS-модулей для проверки в ограниченной среде Chromium; сайт GitHub Pages использует обычные внешние ES-модули и нативные Workers. Протокол численных экспериментов формируется функциями именно этого проекта, а не произвольным графическим редактором.

```text

styles.css, app.js          Интерфейс и графики

report/                     PDF, исходный текст, графики и измерения
tests/                      Автоматические проверки
src/                        Реализация алгоритмов
docs/                       Задание и эталон для F1
tools/                      Воспроизводимость результатов (не нужны на сайте)
```

**Оговорка к методичке:** она требует реализации адаптивного алгоритма именно из лекции, но материалы самой лекции не были приложены. Поэтому вместо неподтверждённого совпадения реализован стандартный метод Сауволы с явными параметрами, что отдельно отмечено в отчёте.
