# Протокол проверки лабораторной работы № 4

## 1. Корректность математических алгоритмов

Тесты запускались на JavaScript / Node.js v22.16.0 без сторонних пакетов:

- `npm test` — 14 автоматических проверок: четыре алгоритма линий × (восемь октантов и обратное направление; вырожденный, горизонтальный, вертикальный случаи), 1681 наклон Брезенхема, точные интенсивности двух соседних пикселей Ву, восьмикратная симметрия окружности, матрица координат, несколько эллипсов и параболическая дуга.
- `npm run test:extended` — независимая расширенная проверка 30 × 30 × 5 = **4500 сочетаний** полуосей и углов эллипса, с проверкой завершения обхода.
- Проверены отрицательные координаты, нулевая длина отрезка, отрицательные углы наклона, смена ведущей оси, `r = 0` окружности.

Замер производительности не подменяет тест корректности; они выполняются отдельно.

## 2. Методика измерения времени

Основная процедура `runBenchmark()` работает с `VirtualGrid(512,512,0,511)` и измеряет генерацию растра через `performance.now()`:

1. Массивы примитивов генерируются заранее псевдослучайным детерминированным генератором, `seed=0x4a31b` для отрезков, `seed=0x9fab7` для окружностей.
2. В каждом пакете отрезков индекс `i % 8` гарантирует наличие всех восьми октантов. Длины от 4 до 90 по ведущей оси, окружности радиуса 2–32.
3. Перед каждой основной серией предусмотрен разогрев 1500 примитивами.
4. Перед стартом таймера виртуальный растр очищается; подготовка входных данных, DOM, Canvas и формирование графиков во временной интервал не включаются.
5. Для основной серии снимаются три значения, итог — медиана. Для точек графиков снимаются два значения, итог выбирается по коду `med()`; две пробы — меньше статистической надёжности, чем три, поэтому небольшие колебания измерений возможны.
6. Бенчмарк пользовательского интерфейса выполняется в Web Worker; сохранённый в архиве исходный JSON получен от консольного Node.js-раннера, который вызывает ту же `runBenchmark()`.

## 3. Фактический сохранённый прогон

Машина: Linux x64, Node v22.16.0, AMD EPYC 9V74; время — миллисекунды. Файл исходных измерений: `benchmarks/measured_node.json`.

| Алгоритм | Число примитивов | Время, мс |
| --- | ---: | ---: |
| Пошаговая линия | 100 000 | 52.231 |
| ЦДА | 100 000 | 53.868 |
| Брезенхем (отрезок) | 100 000 | 32.359 |
| Ву (сглаживание) | 100 000 | 94.995 |
| Брезенхем (окружность) | 50 000 | 197.929 |

Из этих измерений `53.868 / 32.359 ≈ 1.665` — отношение времени ЦДА к Брезенхему. Нельзя переносить это ускорение на другие языки, процессоры и движки без новых замеров. В отчёте дополнительно приведены три графика на основании сохранённых точек массива `countSeries`, `lengthSeries`, `circleCountSeries`.

## 4. Проверка интерфейса

Проведена автоматизированная проверка в Chromium: переключение семи алгоритмов, построение точек на сетке и осей, таблица шагов, кнопка смены октанта, масштаб, визуализация графиков из сохранённых значений. Зафиксированы изображения для отчёта; в наблюдаемом сценарии ошибок JavaScript не обнаружено.

**Ограничение тестовой среды:** автоматический браузер не позволяет перейти на локальный HTTP-адрес из этой среды. Для проверки использована загрузка *тех же исходных модулей* в изолированную страницу браузера, без изменения логики визуализации. Это подтверждает работу клиентского кода, но не заменяет финальную ручную проверку опубликованного GitHub Pages URL.

## 5. Проверка публикации

Публичный URL ещё не внесён: публикация требует доступа к аккаунту владельца. Перед сдачей необходимо выполнить действия из README, открыть сайт в приватном окне браузера и проверить, что веб-приложение общедоступно.
